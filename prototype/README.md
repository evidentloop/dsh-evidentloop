# DSH 变更评审交互演示

把现有评审台适配为 DSH Desktop 插件形态：左侧「变更评审」先进入交付列表，对话交付卡片直接进入评审台；评审台保留基线的文件树、单双栏 Diff、问题卡片、行号定位、标记非问题与筛选；整批说明在主区域阅读，当前文件说明在下方。

演示只读写本目录，数据由本仓当前 Git 改动生成；审查说明、问题、证据与历史交付为示例结果。不安装依赖、不联网、不调用真实模型。

## 打开方式

直接以 `file://` 打开 `prototype/index.html`，或在任意静态文件服务器下打开。所有资源均为本地文件，页面不会发出网络请求。

默认进入交付列表；左侧「变更评审」打开列表，对话交付卡片「评审本次变更」直接打开评审台。评审台顶栏「返回」按来源回到对话或列表。

## 页面层级与交互

- **交付列表**：页头副标题即工作区切换器（搜索、文件夹图标、第二行「所属仓库：…」或「不是 Git 仓库」、当前项打勾）与「N 个交付」，右侧搜索与设置齿轮；工作区按所属仓库归并交付，非 Git 工作区显示现有前置提示；同一仓库有多个工作区时设置面板注明共享。交付以自适应卡片网格呈现。卡片头部为标题与「…」菜单（只有「删除」）；需求编号不上卡片，可被搜索；正文为分支 · 最新时间、状态胶囊（待审 / 发现 N 个问题 / 未发现问题 / N 个文件待审 / N 个文件审查失败 / 审查失败 / N 条结论未通过校验 / 代码读取不完整 / N 项待处理；有问题但不完整时并排两个胶囊）与可选交付目标；底部左侧「最近会话：标题 · 相对时间」（已归档时为普通文字加「（已归档）」并带提示，已删除时不显示），右侧固定两个入口「变更说明」与「进入评审 →」；整张卡片点击等同「进入评审」，底栏链接与入口点击不触发整卡；悬停时边框高亮、标题变为品牌紫；同一行卡片等高，列数随宽度变化。审查状态与关联会话的判定各自只有一处实现（`src/status.js`），供列表、评审台与导出共用。
- **交付区卡片**：只显示审查状态、需求待确认摘要（有需求依据时）与实心紫色主按钮「评审本次变更」；不显示文件数与增删行。审查结束前不显示「0 问题」。
- **评审台**：一次交付的最新审查记录或所选更早审查记录。顶栏显示「返回」、交付标题 · 分支 · base 短 SHA … 工作树 · 审查时间下拉「11-07 18:18 ▾」；下拉列出全部审查记录（时间、基于的 commit、是否含未提交改动、问题数、来源会话链接），选中后原地切换。查看更早记录时，顶栏下方显示 32px 横幅「正在查看 … 的审查记录（只读）· 打开最新审查 →」，顶栏不再另加只读标签，处置按钮隐藏。主区域有整批变更说明与文件 Diff 两种视图：从交付卡片进入先显示整批变更说明；从交付列表按所点入口。工具栏最左、收起文件栏按钮之后是纯文字两段切换「变更说明 / 文件对比」；点文件树或说明中的文件、行引用切到该文件对比并定位。下方面板只放当前文件说明，默认收起。
- **发回会话**：导出菜单中的「修改问题」与「补充说明」两项。点击时锁定内容、审查记录、目标开发会话、模板与最终正文；子代理会话归一到主会话；输入框为空时直接写入并打开该会话，已有内容时先预览，由用户选择「追加到草稿末尾」或「复制到剪贴板」；同一模板与正文不重复追加；没有开发会话时不可用；「补充说明」在没有通过校验的说明时不可用；目标会话被删除、改属其他项目或评审台已切换审查记录时不改选其他会话，降级为复制到剪贴板并提示原因；不会自动发送。

## 与基线的差异

### §1.1 页面层级

新增交付列表与交付区卡片；评审台由列表或卡片进入，返回路径按来源区分。更早的审查记录从顶栏审查时间下拉原地切换进入，只读；交付卡片不再展开历史行。

### §1.2 全页适配

- 去掉固定高度，评审台占满主区域剩余高度。
- 拍平 个人原型卡片外壳：无外层卡片边框、无灰色缝隙；四周统一页面边距，面板之间用 1px 分隔线。
- 文件栏、整批说明主区域、Diff、当前文件说明面板各有唯一滚动区，页面本身不滚动；双栏同步滚动保留。
- 文件栏可收起与拖宽，宽度上限 32%；当前文件说明面板在 Diff 下方、可拖动高度。
- 删除全屏按钮及其状态；需要更大阅读区时使用 DSH 侧栏开关或系统全屏。

### §1.3 替换与移除

| 基线元素 | 本演示 |
|---|---|
| 个人原型宿主外壳 `host.css` / `host-shell.js` | 删除；换成 DSH Desktop 模拟外壳（左侧「变更评审」、对话交付卡片）。 |
| 顶栏 MR / 流水线信息 | 换成交付标题 · 分支 · base 短 SHA … 工作树 · 审查记录时间。 |
| 单文件「查看报告」面板 | 改名「查看说明」：**变更摘要**（逐条要点，符号以行内代码写在要点里，可点击跳行）→ **代码评审**。不显示文件名标题、「新增 / 模型解释」标签或关键符号表。 |
| 文件名链接「在 GitLab 中查看」 | 改为「在编辑器中打开」，只记录意图并提示。 |
| GitLab 未授权 / 跳转 | 换成非 Git、目标分支不明、未配置模型、split index 前置提示。 |
| 「GitLab 未返回 diff」「diff overflow」 | 改为二进制、超过大小上限、按敏感规则或第三方目录排除、符号链接、子模块、冲突。 |
| 点赞 / 点踩、使用指南、全屏 | 移除。 |
| 旧的静态演示数据文件 | 删除；改由 `scripts/build-data.mjs` 生成本仓真实 diff + 合成审查结果。 |

### §1.4 新增四项

1. 工具栏「变更说明 / 文件对比」两段纯文字切换：切到文件对比回到上次查看的文件，没有则打开第一个文件。文件筛选只保留「全部文件」「风险文件」（存在待审文件时增加「待审文件」），相邻审查记录的差异只在导出「与上次审查相比」中列出；单栏/双栏改为一个图标按钮，悬停分别提示「切换为双栏」「切换为单栏」。顶栏不插播「未通过校验」裸链接：告警沉入变更说明正文顶部通告卡，Diff 视图占高为 0；左上角保留 16px 文件树图标。
2. 整批说明末尾的「需求依据」：来源、获取时间、原文、需求编号与「添加需求依据」，默认折叠。
3. 设置中的「扩展提示词」：工作区级 Markdown，最多 20000 字；设置行只保留单一「编辑」入口，弹窗左侧编辑、右侧使用同一净化渲染预览，可导入 .md、清空；修改后评审台提示「扩展提示词已更改，Review All 后按新要求审查」，Review All 时生成新审查记录并让全部文件回到待审。
4. 导出菜单「发回会话」分为「修改问题」与「补充说明」两个模板：前者整理未处置问题与未对齐 / 待确认条目；后者由所选审查记录的结构化数据拼接来源、目标、功能做法与引用，Skill 名称留给用户在草稿中填写。两者都写入开发会话输入框草稿并打开该会话，不自动发送；两个模板都从同一审查状态写一行「审查状态：完整 / 审查不完整 · 未展示数量与原因」；已有草稿时先预览，可追加或复制，去重看目标会话当前草稿是否仍含这段正文。

### §1.5 规则

- 主区域在整批变更说明与文件对比之间切换；从交付卡片进入先显示整批说明，从交付列表进入保留上次视图。点文件树（含当前文件）或说明中的文件、行引用切到 Diff 并定位；两段切换随时互切。整批说明时文件树当前文件只保留弱选中，单栏/双栏切换隐藏且不移动其他控件。
- 下方面板只放当前文件说明，默认收起，点文件头「查看说明」展开；整批说明不在下方面板。
- 整批说明共 6 块，先结论后依据：结论（交付目标、「本次改动」最多 5 条，由下方同一份功能列表生成，每条「功能标题：做了什么 · N 个文件」并可滚到该功能；一行审查结论，可点击跳到问题或审查覆盖）→ 按功能的变更（目的与实现方式、行为影响随功能、文件只显示数量）→ 需求对齐（未对齐 / 待确认在前，已对齐默认折叠，需求外改动单列）→ 问题（按严重度汇总、可跳转、含证据未通过校验的数量与原因）→ 审查覆盖（已审、跳过原因、失败原因）→ 需求依据（默认折叠、放最后）。不单独展示 highlights。
- 列表一律无序列表；「代码事实 / 模型推断」按小节标一次；行为影响属于模型推断，不把原型局限写成影响或要点。
- 文件数只出现在筛选标签；顶栏不重复统计。
- Review All 位置只显示需要操作的状态：待审时 Review All；排队、运行中（可取消）；已取消（重新审查）；失败（重试）；审查不完整时显示短句「审查不完整 · N 条未通过校验」，点击切到整批说明的问题与审查覆盖。全部审完且完整时为空。
- 当前文件说明的代码评审每个问题只占一行「严重度 · 标题」，点击定位到 Diff 中的问题卡片；完整问题、证据与建议只在 Diff 卡片里出现一次。
- 界面上的文件、行引用都可点击跳转；显示「文件名:行」，悬停显示完整路径，只指向文件的引用不带行号。没有目标的条目是普通文字，不做成禁用按钮。sha256、审查记录 ID、inputSha、promptVersion、追溯信息不在界面显示，只进入导出内嵌数据。
- 问题卡片头与文件面板的问题行显示「类别 · 严重度」；类别为中性标签，严重度只在标签出现一次，P0/P1 红色、P2 橙色，安全类加盾牌；正文使用「问题 / 影响 / 建议」与证据块。问题卡片上不显示依据标记；「代码事实 / 模型推断」只在变更说明各小节标题标一次。标记与恢复先确认「确认标记为非问题？」/「确认恢复为有效问题？」。
- 需求对齐先列「未对齐 / 待确认」，已对齐默认折叠，「需求外改动」单列；无需求依据时只显示「未提供需求依据」一行。
- 设置面板统一包含自动模式（agent 每轮结束、代码有改动时自动审查）、目标分支覆盖、扩展提示词、导出默认项；列表与评审台共用。需求编号在「整批变更说明 → 需求依据」中手动填写，存入当前交付的 `externalRef`。
- 导出菜单为「变更日志（Markdown）」「评审报告（HTML）」「修改问题」「补充说明」与溢出项「全部重新审查」；有审查记录就能打开菜单，逐项判断可用性；补充说明不可用时在项内写「先完成审查」；菜单打开时不显示提示气泡；菜单项标题与说明分行。强制重审开始时旧整批说明立即失效；运行中、取消或失败后的导出与发回草稿只写文件事实与当前状态，不把旧说明当成本次说明。

### §1.7 视觉

视觉按 `assets/ui-spec.md`：中性色使用 DSH `--dsw-alias-*` 变量（带回退值），强调色为品牌安静紫（浅色 `#6754c8` / 深色 `#b5a4f2`），每屏最多一个实心紫色主按钮；状态色只表达状态（红、橙、绿、灰）；类别与依据标签中性化；支持系统深色模式，无硬编码白底；界面不出现蓝色。Diff 使用 diff2html 官方配色并随主题初始化 `colorScheme`，代码高亮浅色用 github.css、深色用 github-dark.css。文件树图标沿用评审台基线的 Material 原色，浅色与深色相同，选中时不改色；文件夹名使用主文字色。产品图标统一为「放大镜 + <>」：左侧导航与交付区卡片使用中性线条版（内联 SVG），导出报告页头使用浅色 / 深色应用图标（随系统主题，内联 SVG）。控制台提供「跟随系统 / 浅色 / 深色」验收开关；控制台收起时标题栏另有「浅色 / 深色」两段切换，选择保存在浏览器本地存储（读写失败时跟随系统），产品界面不加主题开关。

## 数据生成

```sh
node prototype/scripts/build-data.mjs
```

脚本只用以下只读 Git 命令：`rev-parse`、`merge-base`、`ls-tree -r -z`、`ls-files -z`（含 `-s` 与 `-o --exclude-standard`）、`cat-file --batch`。按 §3.2 统一环境为 `GIT_OPTIONAL_LOCKS=0`、`GIT_NO_LAZY_FETCH=1`、`GIT_TERMINAL_PROMPT=0`，并加 `-c core.fsmonitor=false`；同时清除继承的 `GIT_DIR`、`GIT_WORK_TREE`、`GIT_INDEX_FILE`、`GIT_OBJECT_DIRECTORY`、`GIT_ALTERNATE_OBJECT_DIRECTORIES`、`GIT_COMMON_DIR`、`GIT_TRACE*`、`GIT_CONFIG*` 等重定向变量，并用显式 `--git-dir` / `--work-tree` 固定本仓；split index 预检与后续读取使用同一仓库、同一 index。不调用 `status`、工作树 `diff`、`add`、`update-index`。读取 index 之前先做 split index 预检，命中即停止且不生成审查记录。

工作树一侧直接读文件字节，不跟随符号链接；base 一侧用 `cat-file` 读取。`prototype/vendor/`、`.sopify/`、`prototype/data/` 等按规则只留元数据或完全省略。`snapshot.js` 同时包含当前审查记录、交付列表、开发会话、历史交付、合成问题 / 证据未通过校验记录与变更理解。

数据按 §2 合同生成：`Delivery` 含当前真实交付与一组示例交付（标明 synthetic，覆盖未发现问题、已合并、部分待审、部分文件失败、整次失败、证据未通过校验、代码读取不完整与多个原因），`everAhead` 为布尔；`workspaces` 提供 4 个虚构工作区（当前仓库、同一仓库的子文件夹、另一个仓库、不是 Git 仓库的文件夹），交付按 `projectKey` 归并；会话覆盖存在、已归档（`archived: true`）与已删除（引用但不在会话表中）三种状态；Snapshot 关联 `deliveryId`；Finding 使用 `category`（logic / security / performance）、`severity`（P0 / P1 / P2）、`ruleSource`、`anchor` 与 `problem / impact / suggestion`；`coverage.withheld` 使用 `{ kind: finding|statement, ref, code }`；变更理解使用 `semantic { items[], status }`、`featureId` 双向关联、`alignment[]` 与 `extras[]`，不再有 `keySymbols`；行为影响全部为模型推断并归入相关功能，原型局限不作为影响或要点。至少包含一条安全类 P0、一条文件级问题、一条 `semantic.status=unclear` 与一条证据未通过校验的记录。

## 验证的内部结构与并行

`tests/verify.cjs` 只保留 CLI、只读守卫、总超时、并行编排、汇总与最终横切；检查体位于 `tests/verify/`：

- `shared.cjs`：每个 context 一份的 runtime（`open/state/shot/check`、颜色与对比度探针、图标提示审计、`currentData`）；
- `core.cjs`：静态检查、采集器与只读守卫自测、验证器故障自测、数据合同与固定入口名；

## 已知限制

- 审查说明、问题、证据与历史交付为示例数据；三条审查记录是同一交付的连续示例版本，只有当前交付的文件清单、行数与 Diff 来自本仓真实 Git 状态。
- 每条示例交付与更早审查记录各有独立的文件清单、功能说明与问题数据；它们仍为合成数据，不是真实历史比对。
- 数据脚本未实现已提交改名检测、clean/process 过滤器与 Git LFS 检测；也不做冻结后二次一致性核对。演示的单文件大小上限为 256 KB（合计 40 个文件、29 个审查目标、11 个跳过）。split index 预检覆盖本地 `.git/config`、`sharedindex.*` 与 index 的 `link` 扩展；全局 / include 配置中的 `core.splitIndex` 未单独枚举，但已转换的 split index 仍会被 `link` 扩展拦截。
- 仓库尚无提交时以空树为 base，`range.kind` 仍标为 merge-base-worktree；后续阶段需明确 unborn 仓库的 range 表达。
- `file://` 下 localStorage 偏好可能不可用；失败时静默回退到默认单栏与展开文件栏。
- 交互式「添加需求依据」会生成新审查记录并让全部可审查文件回到待审，但 `inputSha` 仍是演示内的简化计算；后续由 host 按 §2 重算。
- 导出为浏览器内演示实现；HTML 按整份文件的 UTF-8 字节限制 3 MiB，超出片段与超长文本会进入省略清单；极端超限时只保留标题、审查状态与省略清单，Markdown 不设总量上限。
- 扩展提示词保存在演示内存，刷新后回到默认；真实 host 的 `rules.json` 规则清单、冻结与持久化在 P2 实现。
- 发回会话使用模拟会话与本地输入框；会话存在性、项目归属与草稿通道在 P2 实测。
- 只读检查同时使用文件清单（路径/字节/sha256/mtime）与 fs.watch 事件，并在结束前等待固定时长排空事件；自测在临时夹具中验证了持久写入、恢复 mtime 的覆写、同步子进程创建后删除等本机样本能被捕获，主运行把守卫根设在本仓与数据根。`.sopify/`、`docs/` 与 `.polish-loop/` 由主脑 / 下一阶段交互打磨并行写入，与原型是否只读无关，因此不纳入清单也不转发监听事件；控制器的 `.git/trae-ai-tob/` 检查点与瞬态 `.git/index.lock` 同理；`prototype/` 与 `.git` 的其余状态仍在守卫范围内。清单加事件是尽力检测，依赖固定等待时长与系统通知的可靠性，不能证明能捕获所有瞬时写入，也不能外推到高负载或通知丢失的场景。监听无法启动时检查直接失败，不降级为「没有写入」。
